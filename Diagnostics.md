# Diagnostics

A diagnostic whose cause is an attribute is reported at that attribute: the second of two attributes that contradict each other (SMP0101), and the `[MapperProfile]` or `[ValueConverter]` of the class for a value it gives (SMP0401, SMP0404, SMP0104). One about the method itself (SMP0001 to SMP0008), the automatic mapping (SMP0402 for a property no attribute names), the construction of the destination (SMP0301, SMP0303, SMP0304, SMP0305) or the unmapped properties of strict mode (SMP0501) is reported at the mapper method, and the other warnings of strict mode (SMP0502, SMP0503) at the attribute of the mapping, or at the method for the automatic mapping.

A warning reported at the mapper method starts at its first attribute, and one reported at an attribute at that attribute, so a `#pragma warning disable` suppresses it only when it comes before that line: before the attributes of the method for one reported at the method (one between the attributes and the method does not). `[SuppressMessage("Usage", "SMPxxxx")]` on the method suppresses both.

A mapper reported with an error gets an implementation throwing `NotImplementedException` in place of none, so that the error is not accompanied by the missing implementation (CS8795); the build fails on the error, so the implementation never runs. A method not `static partial`, or in a type not `partial` or file-local (SMP0001), which the generated code could not implement, gets none; one declared without an accessibility modifier gets one without it, as it is declared.

## Mapper method

| ID | Severity | Description | How to fix |
|---|---|---|---|
| SMP0001 | ❌ Error | `[Mapper]` method is not `static partial`, or a type containing it is not `partial` or is file-local (`file`): the generated code declares the containing types again, outermost first, in a file of its own, where a file-local type is not seen | Declare the method as `static partial`, and its containing types as `partial` and not `file` |
| SMP0002 | ❌ Error | `[Mapper]` method has no parameter, or returns `void` without a destination parameter after the source (a return-type mapper takes the source, and a void mapper the source and the destination, each followed by the custom parameters) | Take the source as the first parameter, and for a void mapper the destination as the second |
| SMP0003 | ❌ Error | `[Mapper]` has two custom parameters of the same type | Give each custom parameter a distinct type |
| SMP0004 | ❌ Error | `[Mapper]` parameter name starts with `__`, which is reserved for the names the generated code declares | Rename the parameter so that it does not start with `__` |
| SMP0005 | ❌ Error | `[Mapper]` parameter has a modifier the generated code cannot work with: `out` on any parameter, or on a struct destination of a void mapper `in` / `ref readonly`, whose members cannot be assigned, or none, which passes a copy the caller never sees filled | Remove the modifier; pass a struct destination by `ref` |
| SMP0006 | ❌ Error | `[Mapper]` source parameter is a nullable value type (`Point?`), which has none of the members of the struct it holds (only `HasValue` and `Value`), so nothing would be mapped | Take the struct itself, and check null before calling the mapper |
| SMP0007 | ❌ Error | `[Mapper]` source or destination is a collection of the framework (a list, a set, a dictionary or one of their interfaces, and the immutable, frozen, concurrent and object model ones, of `System.Collections` and the namespaces under it), a class deriving from one (`class ItemList : List<Item>`), an array or a tuple: a mapper maps the members of an object, so it would map the members of the collection (`Count`, `Capacity`) and none of its elements, or could not create an array or a tuple. A type of its own only implementing `IEnumerable<T>`, such as a page of items with its count, is mapped by its members | Map the elements with a mapper of the element type (`source.Select(ToDto).ToList()`), or map a type holding the collection with `[MapCollection]` |
| SMP0008 | ❌ Error | `[Mapper]` method returns by reference (`ref` or `ref readonly`), while it returns the destination it creates, which the reference would have to point to | Return the destination by value |

## Mapping attributes

| ID | Severity | Description | How to fix |
|---|---|---|---|
| SMP0101 | ❌ Error | Multiple mapping attributes target the same destination property, or one maps a member as a whole and another a member of it through a dotted path (`Child` and `Child.Value`), which cannot both apply, or `[MapIgnore]` and an attribute mapping the same target, which contradict each other, whichever the attribute is (`[MapIgnore]` of a member with dotted paths into it is allowed: the member is left out of the automatic mapping, and the paths are applied) | Leave a single mapping attribute per destination property, map the members of a member one by one, and remove `[MapIgnore]` from a target an attribute maps |
| SMP0102 | ❌ Error | `[BeforeMap]` method does not match `(Source, Destination)` or `(Source, Destination, customParams...)`, the source and the destination going to parameters of their types, or, by value, of a base class or an interface they convert to (a struct to its own type only), or the call is ambiguous or binds to a method not matched | Correct the `BeforeMap` method signature |
| SMP0103 | ❌ Error | `[AfterMap]` method does not match `(Source, Destination)` or `(Source, Destination, customParams...)`, as for `[BeforeMap]` (SMP0102) | Correct the `AfterMap` method signature |
| SMP0104 | ❌ Error | Converter method is not found, or does not match `(SourceType)` or `(SourceType, customParams...)` returning the target property type or a type converting to it implicitly, the source value going to its first parameter as described below, or the call is ambiguous or binds to a method not matched | Add the converter method, or correct its signature |
| SMP0105 | ❌ Error | Converter parameter types match but the return type of the method the call binds to does not convert implicitly to the target property type (for a constructor argument, the type of the parameter), as for `[MapUsing]` (SMP0202) | Change the converter return type to the target property type, or to one converting to it implicitly |
| SMP0106 | ❌ Error | Property condition method does not match `(SourceType)` or `(SourceType, customParams...)` returning `bool`, the source value going to its first parameter as described below, or the call is ambiguous, binds to a method not matched, or binds to one not returning `bool` | Correct the condition method signature |

These methods, `[MapUsing]` methods (SMP0201) and the mapper methods of `[MapCollection]` / `[MapNested]` (SMP0210 / SMP0211) also do not match when a parameter modifier cannot take its argument. No modifier and `in` take any argument, `ref readonly` takes a variable, `ref` takes a writable variable, and `out` takes none. The arguments are:

- Values: property values, the elements of an `IList<T>` / `IReadOnlyList<T>` (which its indexer returns), and the format string
- Writable variables: parameters of the mapper taken by value or by `ref`, the instance the generated code creates, and the elements of an array, `List<T>` or `Memory<T>`
- Read-only variables: `in` / `ref readonly` parameters of the mapper, the elements of any other collection (`ImmutableArray<T>`, `ReadOnlyMemory<T>`, or read with `foreach`), and the culture given to a `CultureInfo` parameter (given to `IFormatProvider` or `object`, the culture is a value)

A generic method does not match either, as the generated code calls these methods without type arguments, nor does one obsolete as an error (`[Obsolete(..., true)]`), which the generated code could not call (CS0619); one obsolete as a warning is called, warning as C# does (CS0618).

A method taking the custom parameters of the mapper (a converter, a condition, a `[MapUsing]` method, a `[BeforeMap]` / `[AfterMap]` callback) takes all of them after its usual parameters, in the order the mapper declares them, each as its type; one taking only some of them, or in another order, does not match.

These methods are static methods found as C# looks up the simple name of the call the generated code makes: in the mapper class and its base classes, or, when none of them has a member of the name the mapper class can access and the call can invoke, in the class containing it and its base classes, and so on outward, and last in the types the `global using static` directives import (the methods they declare, not those they inherit nor extension methods; a `using static` directive of one file only is not seen from the generated file). The first class having such a member is the only one looked in, as in C#, even when its methods do not take the arguments, which is then reported as not matching; a member the call cannot invoke (a property or a field not of a delegate type, a nested type) is passed over. A method of a derived class hides one of a base class of the same signature, and an instance method is not taken.

The value goes to the first parameter of a converter, a condition or a `[MapUsing]` method (the source member, or the source of `[MapUsing]`) as its type; to a parameter taken by value, as a type it converts to implicitly (a base class or an interface, boxing, a wider number, a nullable struct, or a user-defined conversion not obsolete as an error); or, as the value it holds, a nullable struct to a parameter of the struct, by value or by `in`, or to a parameter taken by value of a type the value it holds converts to implicitly (a converter or a condition, which is then called for a value only, as a method whose parameter does not take null, as it is for a value going through a user-defined conversion whose operator does not take null; a method taking the struct itself goes first, then one taking the nullable struct by a conversion, then one taking the value it holds by a conversion). A parameter taken by `in` takes the type of the value, or of the value a nullable struct holds, only. Of the overloads, the one the call binds to is used, as C# binds it: one taking the type of the value before those taking it by a conversion, and of those, the one whose parameter is the most specific (a class over its base class or interface). The call has to bind to the method chosen, among all the static methods the name is looked up as: a method of a derived class taking the value leaves out those of its base classes, and one taking by value goes before one taking by `in`, and such a method matched is used instead. A call that is ambiguous (CS0121), that binds to a method taking the value by an explicit conversion, or that binds to a method not matched (a generic one, one taking the arguments with optional parameters or `params`, one taking the custom parameters as other types, or one obsolete as an error) matches nothing (SMP0104, SMP0106, SMP0201). A call binding to a method that returns another type is reported by its return type (SMP0105, SMP0202, and SMP0106 for a condition).

A `[BeforeMap]` / `[AfterMap]` callback takes the source and the destination as their types, or, to parameters taken by value, as base classes or interfaces they convert to by an implicit reference conversion; a struct goes to its own type only, as the callback would write into a boxed copy. The custom parameters go to parameters of their own types. Of the overloads, the one the call binds to is used, as for a converter, and an ambiguous call, or one binding to a method not matched, is reported (SMP0102 / SMP0103).

An element mapper given to a collection converter is passed as a delegate, so its parameters have to match those of the delegate (by value for `Func` / `Action`). The methods of a `[ValueConverter]` class (including the overload taking the culture and the format, called when `Culture` is set) and of a `[CollectionConverter]` class take values, and are reported the same way with SMP0104.

A converter class that lacks a method the generated code calls is reported with SMP0104 as well, instead of a compile error in the generated code:

- With `Culture`, the overload `(SourceType, culture, format)` of each specialized method used, whose culture parameter takes a `CultureInfo` (such as `IFormatProvider`) and whose format parameter takes a `string`
- The generic `Convert<TSource, TDestination>` (named by `Method` of `[ValueConverter]`) that a user converter falls back to
- The method of a collection converter for the target (`ToList`, `ToArray`, `ToHashSet`, ... by the target type, or the `Converter` of `[MapCollection]`), called as `Method<TSourceElement, TTargetElement>(source, mapper)`: it has to take the source collection, meet the constraints of its type parameters, and return a collection the target property takes

A void mapper of `[MapCollection]` / `[MapNested]` fills an instance the generated code creates with `new()`, so it matches only when the target type allows that (a struct, or a class that is not abstract with a constructor callable without arguments and no required members that constructor leaves unset); otherwise SMP0210 / SMP0211 are reported, unless a returning mapper of the same name can be used.

The mapper of `[MapCollection]` / `[MapNested]` matches when the source (element) goes to its parameter as its type, or by an implicit reference conversion to a parameter taken by value, or, as the value it holds, a nullable struct to a parameter of the struct (not through a collection converter, which takes the mapper as a delegate); and when its result goes to the target (element) as its type, by an implicit reference conversion, or as the value of a nullable struct target. The instance created for a void mapper goes to its parameter as its type, or by an implicit reference conversion to one taken by value. Of the overloads matching, one of the types themselves is taken over one through conversions; two of other types matching through conversions alike, which would make the call ambiguous (CS0121), are reported as not matching. The call the generated code makes binds among all the static methods the name is looked up as (see above), as C# binds it: one binding to another method matched uses it, and one binding to a method not matched (a more specific one returning another type, a generic one, one with optional parameters or `params`, or one obsolete as an error), which would be an error in the generated code, is reported as not matching.
